# 文档编写规范

## 语言与范围

- 面向服主的页面使用简体中文；代码、路径、命令、枚举和值保持原样。
- 写入已实现行为前，必须以 `ModuleId`、`CommandAction`、对应 `*Config`、默认生成配置和 Schema 交叉核对。
- 规划、候选方案和旧需求只放 `docs/archive/`，并标注为非当前功能。
- 不在 README、入门页或运维页维护第二份模块字段、默认值或命令表；改用链接指向真源。

## 模块主说明

`docs/modules/<module>.md` 使用以下顺序。没有适用内容时写明“不适用”及原因，不能静默省略。

1. 用途、适用场景和依赖模块。
2. 根开关及禁用后的运行行为。
3. 配置路径、首次生成行为、格式版本与重载命令。
4. 命令、默认权限与别名表。
5. 配置字段表：类型、必填、范围、默认值和错误行为。
6. 最小可用严格 `json` 配置。
7. 带注释的 `jsonc` 教学配置。
8. 高级场景与外部引用。
9. 奖励、占位符和公共模板的使用位置。
10. 数据保存、备份和不可更名的稳定 ID。
11. 热重载后的即时行为、验收步骤与常见故障。

成就主页面只维护“场景 -> 示例文件 -> 适用条件”的索引；完整示例只保存在 `docs/examples/achievement-examples/`，以避免同一 JSON 出现多份。

## 配置与示例

- `.json` 必须能直接解析、复制到目标文件并通过对应 Schema 的基本约束。
- `.jsonc` 仅用于教学；明确提示需要去除注释，并链接严格 JSON 或目标路径。
- 每组示例目录提供 README，写明目标配置文件、前置模块、适用 `format_version`、是否需要额外定义称号或模板，以及应使用的重载命令。
- 奖励、称号、物品和模板 ID 在示例说明中必须与文件完全一致。已上线的活动、成就或奖励 ID 不得建议原地改名。

## 链接与历史兼容

- 相对链接优先；链接到仓库文件时不得使用机器绝对路径。
- 旧路径保留简短 `redirect` 页面，正文只给出迁移说明和真源链接。
- `archive/` 页面可以被旧链接直接访问，但不得从 `docs/index.md`、README 或新手路径主动导航。
