# 备份与恢复

## 建议备份集

一次可恢复的备份至少包含同一时点的以下内容：

| 内容 | 为什么必须备份 |
| --- | --- |
| `config/omnitools/` | 根开关、模块定义、统一奖励、权限和文本配置。 |
| 服务器世界目录及其 `data/` | 玩家进度、钱包、称号、奖励账本、云仓、礼包、技能和占卜等 SavedData。 |
| `logs/` 与 `crash-reports/` | 用于判断问题发生前后和收集异常堆栈。 |
| 当前模组 JAR 与服务端版本记录 | 防止恢复旧世界后使用了不兼容的二进制文件。 |

不要把只复制 `config/omnitools/` 当作数据备份；也不要只复制 `world/data/` 当作完整世界备份。配置和世界数据的版本需要成对保留。

## 日常与变更前流程

### 日常备份

优先在服务器正常停止后复制上述备份集，并以日期、服务器版本和用途命名，例如：

```text
backup-2026-09-20-before-shop-update/
```

至少保留一份最近可启动备份和一份变更前备份。备份完成后，随机抽查目录中是否同时存在配置和世界数据；不要只依赖压缩任务“显示成功”。

### 修改配置前

1. 记录准备修改的模块、目的和回滚点。
2. 备份 `config/omnitools/`；涉及发奖、钱包、商店、云仓、礼包、技能或占卜时，同时备份世界 `data/`。
3. 修改后先执行相应重载。
4. 重载失败时，运行中的旧快照会保留；恢复编辑前的配置文件，再次重载即可回到原状态。
5. 重载成功后，用测试账号完成一个最小流程，再开放给玩家。

## 恢复顺序

### 仅配置错误

1. 不要删除世界数据。
2. 从备份恢复 `config/omnitools/` 中对应文件，或按错误中的字段路径修正后执行 `/omnitools reload`。
3. 使用 `/omnitools diagnose` 确认配置已发布、模块状态正常。

### 数据异常、物品争议或不确定交易

1. 立刻停止相关玩家继续操作；云仓争议时建议先停服。
2. 复制当前 `data/`、配置和日志到一个新的事件备份目录，禁止覆盖旧备份。
3. 记录玩家 UUID、发生时间、命令/界面、操作 ID、物品或货币摘要。
4. 先使用只读诊断：`/omnitools diagnose operation <操作 ID>`、`rewards inspect`、`package inspect`、`shop audit` 或 `storage recovery inspect`。
5. 只有当证据能确认操作前或操作后页面/奖励状态时，才使用对应 `resolve` 命令；具体语法见[命令与权限操作手册](commands-and-permissions.md)。

### 回滚整个服务器

1. 完整停止服务器。
2. 将当前服务器目录另存为“事故现场”，不要直接删除。
3. 还原同一批次的世界目录、`config/omnitools/`、模组 JAR 和服务端版本。
4. 启动后先查看配置加载与恢复日志，再让管理员登录验证钱包、云仓和奖励箱。
5. 在验证完成前不要允许玩家领取、购买、存取或重复兑换；否则会混入新的不可判定操作。

## 云仓恢复特别规则

云仓 journal 的状态不是普通缓存：

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| `COMMITTED` | 已有完成证据 | 不要再次恢复。 |
| `ROLLED_BACK` | 已按操作前快照恢复 | 不要再次恢复。 |
| `PREPARED` | 操作边界已记录，但尚待确认 | 先检查日志、玩家背包和页面快照。 |
| `QUARANTINED` | 启动恢复无法安全判定 | 保持隔离，管理员人工裁决。 |

对 `PREPARED` 或 `QUARANTINED`，先执行 `storage recovery inspect`，再根据物品是否已经在玩家背包/云仓页面中选择 `commit` 或 `rollback`。恢复命令只处理云仓页面，不能替代对玩家背包的人工核对。

## 不要做什么

- 不要删除 `world/data/`、journal、奖励账本或云仓数据来“解锁”玩家。
- 不要把一次异常操作当作普通礼包、签到或商店交易重新发放。
- 不要在不确定交易上自动退款、自动补发或反复点击重试。
- 不要用不同版本的模组 JAR 覆盖旧世界后再宣称回滚完成。

这些行为会清除证据，导致原本可恢复的问题变成无法判断的重复发放或永久物品损失。

备份至少包含：`config/omnitools/`、世界目录下的 `data/`，以及完整世界目录。在线修改配置前先备份，再执行 `/omnitools reload`。

恢复时先停止服务端，恢复同一批配置与世界数据，再启动验证。不要用删除 `SavedData` 的方式解决奖励、货币或称号问题；应使用奖励账本命令定位和结案。
